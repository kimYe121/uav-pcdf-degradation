# 这一周：一次失败驱动的复现笔记

> 这是一份个人学习记录，不是论文导读。记录的是"想复现 ICCV 2025 的 PCDF，
> 结果一路踩坑"的过程：每个问题只写四件事——现象、原因、怎么解决、教训。
> 结论先行：**baseline 已经超过论文（59.43 vs 58.4），但 PCDF 的三模块增益还没复现出来；
> 目前最大的嫌疑是条件引导没有真正进入融合模块。**

## 0. 背景

- 数据：ATR-UMOD，RGB-IR 配对、旋转框、11 类、六类成像条件标注，640×512。
- 目标：PCDF（SCPL + PCD + CDF），三阶段训练；验收线是自己的 test mAP50 ≥ 60。
- 机器：RTX 4060 Laptop 8 GB，batch 16 跑 baseline、batch 8 + 梯度累积 2 跑 stage2。

三阶段协议：

| 阶段 | 训练什么 | 产出 |
|---|---|---|
| stage 0 | 双流 YOLOv5s + concat（baseline） | 一个能用的检测器 |
| stage 1 | 只训 SCPL + CDF（检测器冻结） | 条件 → 模态权重的先验 |
| stage 2 | 全管线（PCD 加入，CDF 作用在 `F_v`） | 最终模型 |

## 1. 口径：val 和 test 差了 16 个点

**现象**：同一个 checkpoint，val 39.6，test 56.1。

**原因**：自建的 val 是从官方 train 里整组留出的跨场景子集，长尾类别极少，
分布比 test 难得多。这不是模型 bug，是口径问题。

**解决**：所有对外数字只用 `--split test`；val 只用于选 `best.pt`；评估统一
`--split both` 同时打印两个口径。

**教训**：先定口径，再谈涨跌。口径没对齐时，任何"提升/下降"的判断都不可信。

## 2. 输入几何：0.8 倍缩小 + 18% 灰边

**现象**：baseline 训练/评估一切正常，但 test 只有 56.1，比论文 baseline 低 2.3；
小目标（中位 20 px）尤其差。

**原因**：`RandomPerspective.size` 的 API 是 `(W, H)`，而配置里的 `imgsz` 是 `(H, W)`。
早期为了绕开"图片被拉成竖图"，命令行反着传 `--imgsz 640 512`，让 warp 输出恰好
是横图；但随后的 `LetterBox(new_shape=(640,512))` 又把 640×512 的图等比缩到
512×410，上下补 115 px 灰边。有效像素只有原生 328k 的 210k（−36%）。

**解决**：
1. `data.py` 按 `(width, height)` 传参；
2. 训练脚本统一 `--imgsz 512 640`，让 LetterBox 的 ratio=1、零灰边；
3. 加了几何回归测试（合成图：正确顺序零灰边，传反必出灰边）；
4. `data.imgsz` 进结构校验，跨几何 `--resume` 直接报错，避免"拿 0.8 尺度的权重按 1.0 续训"。

**结果**：原生几何下 baseline test 从 56.10 → **59.43**（+3.33）；中位框从 32.8 px 回到 41.0 px。

**教训**：形状对不代表几何对。张量永远是 `(H, W)`，只有灰边比例和 `ratio_pad`
能暴露"内容被缩小"这件事。验证几何要用数值（`ratio_pad`、内容像素、框中位尺寸），
不要用"看起来正常"的图。

## 3. 可视化框不贴目标：别用各向异性 warp"修"

**现象**：预测框整体偏移，画在原图上几乎全错位。

**原因**：评估管线做了 letterbox（等比缩放 + 居中补边），可视化却按"直接 resize"
反算坐标。

**解决**：逆变换 = 先减 pad、再除 r；用四角点做旋转框反算。曾试过把评估改成
各向异性 warp 来"对齐"，test 直接掉到 37.12——那不是修复，是把训练/评估几何改坏。

**教训**：先证明训练和评估是同一几何（打印 `ratio_pad`），再修可视化；
坐标系问题要分层验证（标注、管线 GT、预测各画一遍）。

## 4. 增强：mosaic + HSV 是负收益

**现象**：加 mosaic(1.0) + HSV 后，ep10/20 的 test 从 36.71/52.71 掉到 31.36/34.92。

**原因**：mosaic 的 2×2 拼图把中位 20 px 的目标压到 ~10 px，在 P3（stride 8）上
只剩一格多；这不是"收敛慢"，是结构性伤害。HSV 还会改 IR 通道的亮度。

**解决**：默认关闭；保留代码和 A/B 数据作为消融证据。

**教训**：COCO 尺度的增强配方不能无脑迁移到小目标航拍数据；A/B 要看匹配轮次的
同口径数字，不看训练 loss。

## 5. 监控口径 bug：stage1 的 val 全是 0

**现象**：stage1 训练时 val 恒 0，`best.pt` 选在 ep5（废权重）。

**原因**：评估函数硬编码视觉引导 `GAP(F_s)`，而 stage1 的 PCD 没训，视觉引导是随机数。
训练梯度走的是文本引导，只有监控走错。

**解决**：`evaluate` 增加 `--guidance {visual,text}`；stage1 监控用文本引导；
stage2 初始化改用 `last.pt`，避开坏 `best.pt`。

**教训**：监控口径必须和训练口径一致；选点规则错了，权重就白训。

## 6. 进程管理事故：taskkill 没验返回码

**现象**：计划 ep20 停训，实际跑到 ep29；随后重启链条又起了一个 trainer，
第二个在首个 epoch 内 OOM。

**后果**：核实过 log.csv 的 epoch 1–29 唯一、metrics 单轨迹，没有混写污染；但浪费了时间。

**解决/纪律**：杀进程后必须验进程表；重启训练前必须确认没有存活 trainer。

**教训**：自动化脚本里每一个"停止/启动"都要有可验证的后置条件，不能只看命令退出。

## 7. stage2 引导协议：条件信号从第 0 轮就被丢掉

**现象**：stage2 只比 baseline 高 0.4（56.49 vs 56.10），论文是 +4.7。

**诊断**（探针，test 1503 张）：

| 干预 | mAP50 | 结论 |
|---|---:|---|
| 原样 | 56.49 | — |
| 打乱引导向量 | 56.28 | 条件引导几乎没用（−0.21） |
| 权重换成另一张图的 | 0.52 | 逐图权重是命脉 |
| 强制 W=0.5 | 51.95 | 逐通道动态选择值 +4.5 |
| 文本 vs 视觉引导余弦 | −0.11 | 两者逐样本不相关 |

**原因**：实现把"引导来源"和"融合对象"绑死：文本 → 原始特征、视觉 → `F_v`。
stage2 从第 0 轮就用随机初始化的 `GAP(F_s)` 引导 CDF，CDF 学会忽略它；
论文的 `L_dt` 本意是"用文本引导训练、测试换 `F_s`"，只有训练期 CDF 真的吃文本，
这条蒸馏才有意义（补充材料 Fig.10 Stage II 也画了 SCPL → CDF）。

**解决**：拆开两个概念，`forward(guidance=..., fuse=...)`；stage2 训练用
`guidance="text", fuse="decoupled"`，测试仍走视觉引导；监控同步改文本口径。

**教训**：模块"接上了"不等于"信号流过去了"。判断一个引导有没有用，最便宜的办法
是打乱它看输出变不变，而不是看 loss。

## 8. 冻结范围：论文只写了冻 CLIP，但放开检测器会让 SCPL 学不动

**现象**：按"只冻 CLIP"训练 stage1，ep10 的 kept=6.00（六个属性全保留），
六个门控概率全在 0.16 附近——门控 10 轮没动。

**对照**：冻结检测器时，stage1 结束 kept=1.74，门控概率分化（weather 0.44 / time 0.33 /
其余 ~0.01）。

**原因**：检测器可训练时，降 loss 的捷径是改检测器，SCPL 拿不到梯度；
冻结检测器才迫使融合模块去学。

**解决**：`train.stage1_train_detector` 默认 False（冻结检测器），保留 True 作为可选项；
PCD 三支在 stage1 始终冻结（前向不经过它们，避免 weight decay 污染随机初始化）。

**教训**：原文有歧义时，用"被训模块是否真的在学"来裁决，而不是靠读句子。
门控 kept 数、概率分布就是最直接的证据。

## 9. 结构性掉点：stage1 一定比 baseline 低

**现象**：stage1 test 56.75，baseline 59.43，掉 2.7。

**原因**：CDF 逐通道 softmax 满足 `w_rgb + w_ir = 1`，融合特征能量
`w² + (1−w)² ∈ [0.5, 1]`，而 baseline concat 是 2。stage1 检测器冻结，
BN/检测头无法吸收尺度变化，于是结构性掉点。

**解决**：接受它。stage1 的产出是门控/CDF 先验，不是最终 mAP；尺度由 stage2
解冻后的检测器吸收。

**教训**：中间阶段掉点不一定是实现错。先把"结构性代价"和"实现错误"分开，
再决定要不要修。

## 10. 显存与内存：8 GB 卡的边界

- stage2 有三支解耦 + 两个辅助头 + CLIP，batch 16 必 OOM；改 batch 8 + 梯度累积 2，
  等效 batch 16，峰值 7.81 GB。
- 15.3 GB 内存下，4 个 DataLoader worker 各持一份数据集副本，出现
  `numpy` 连 1.88 MB 都分配失败；降到 2 个 worker 后正常。
- 教训：训练崩在数据加载，不一定是数据 bug；看 traceback 是 worker 侧还是主进程侧。

## 11. 目前没解决的

1. **CDF 对条件引导不敏感**：stage1 的 `|ΔW|`（打乱引导）只有 0.014，
   打乱池化是 0.061；论文 Eq.10 的投影输入只有 `F_s`，而我们的实现
   （按 Fig.4 读法）是三路输入，条件被稀释。下一步是"只吃引导"的 CDF 重训。
2. **`L_dt` 只对齐 batch 边缘矩**：CMD 不配对样本，文本/视觉引导逐样本余弦 ≈ 0。
   如果改成只吃引导仍不涨，就把 `L_dt` 改成逐样本对齐。
3. **PCDF 净增益**：目前只有 baseline 超过论文，三模块的增益还没证实；
   stage2 的正确协议（文本引导 + `F_v`）只在本地验证到代码路径，最终数要等服务器跑完。

## 12. 工程习惯（这一周真正学到的东西）

- **先口径、后模型**：val/test、几何、评估参数，任何一项没对齐，涨跌都不可信。
- **探针优先于重训**：打乱输入、替换权重、固定门控——这些前向实验几分钟就能否定一个假设，
  比 4 小时训练便宜两个数量级。
- **每个 run 留痕**：`command.txt`、`config.yaml`、`log.csv`、`metrics.json`、`summary.json`，
  加一份 `STATE.md` 记录决策与事故。没有这些，三天后自己也说不清哪个权重是什么口径。
- **别把 bug 修在命令行**：`--imgsz` 反着传能"绕开"竖图，但把 0.8 灰边留在了管线里。
  正确的位置是数据和配置层，并配回归测试。
- **对论文保持两种读法**：原文没写死的地方（冻结范围、引导来源），用实验裁决；
  但每次只改一个变量，并记录证据。
